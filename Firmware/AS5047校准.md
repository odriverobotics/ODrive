# AS5047P 磁编码器零位校准

本文档说明本工程中 AS5047P 磁编码器零位校准的实现原理、CAN 协议、操作流程与排错。
移植自 `MC_V0.5.6` 工程，代码位置与命令 ID 已适配本工程（`ODrive_V0.5.6_modify`）。

相关手册见源工程的 `磁编AS5047P-ATSM.pdf`（重点：第 13~18 页寄存器与 SPI 时序、第 27~29 页 OTP 烧写流程）。

---

## 1. 目标

让电机上电后**不需要跑 `AXIS_STATE_ENCODER_OFFSET_CALIBRATION`** 就能直接进入闭环控制，做法是用
"开环直流对齐 + 硬件零位写入"替代 ODrive 原本的开环扫掠标定。

两条可选路线：

| 路线 | 做法 | 掉电后 | 适用 |
|---|---|---|---|
| **A：软件偏移** | 只写 `phase_offset = X`（存 flash） | 保持有效 | 单台调试、少量样机 |
| **B：硬件零位** | 写 ZPOSM/ZPOSL（易失）或烧 OTP（永久） | 易失版会丢；OTP 永久有效 | 量产：烧一次 OTP 后退 `phase_offset = 0`，所有机器用同一份固件 |

## 2. 原理

### 2.1 AS5047P 是逐帧流水线 SPI

手册原文：

> An SPI transaction consists of a 16-bit command frame followed by a 16-bit data frame
> The SPI read is **sampled on the rising edge of CSn** and the data is transmitted on MISO with the next read command

即：**命令帧和数据帧各占一个 CS 低电平周期**，不是拼在同一个 CS 段里。所以

- 读操作：本周期发命令，下周期发 NOP 收回数据；
- 写操作：本周期发写命令，下周期发数据帧；
- **每个采样周期只发一帧**，所有 SPI 事务 `length = 1`。

（早期实现曾把写命令和数据拼成一个 `length = 2` 的 CS 段，实测写不进去，已废弃。）

### 2.2 寄存器

| 地址 | 名称 | 说明 |
|---|---|---|
| 0x3FFE | ANGLEUNC | 未做动态误差补偿的角度（原始角） |
| 0x3FFF | ANGLECOM | 做了动态误差补偿的角度 |
| 0x0016 | ZPOSM | 零位偏移高 8 位 = ANGLE[13:6] |
| 0x0017 | ZPOSL | 零位偏移低 6 位 = ANGLE[5:0] |
| 0x0018 | SETTINGS1 | 客户设置 1（bit0 是出厂位，烧写时必须为 0） |
| 0x0019 | SETTINGS2 | 客户设置 2 |
| 0x0003 | PROG | 编程寄存器：PROGEN=bit0，OTPREF=bit2，PROGOTP=bit3，PROGVER=bit6 |

两个要点：

1. **ODrive 每周期发的 `0xFFFF` 就是"读 ANGLECOM(0x3FFF)"**：
   `bit14 = R/W = 1`、`ADDR = 0x3FFF`、`bit15 = 偶校验 = 1`，完全合法。所以实际使用的角度寄存器是 ANGLECOM。
2. **ZPOS 是整体平移刻度**：`ANGLECOM = (原始角 − ZPOS) mod 16384`。只要 X 是在**电气 0 位置**测到的原始角，
   把它写进 ZPOS 后，无论转子后来停在哪里，计数都会**恰好在电气 0 处归零**。

### 2.3 相位计算与两种偏移的换算

```cpp
corrected_enc    = count_in_cpr_ - phase_offset;          // encoder.cpp
interpolated_enc = corrected_enc + interpolation_;        // 静止时 interpolation_ = 0.5
ph               = elec_rad_per_enc * (interpolated_enc - phase_offset_float);
phase_           = wrap_pm_pi(ph) * direction;            // 仅当 is_ready_ 为 true 才更新
```

静止时 `interpolation_ = 0.5`，代入得：

```
ph = elec_rad_per_enc * (count_in_cpr_ - phase_offset + 0.5 - phase_offset_float)
```

**真正生效的等效零位偏移（计数）= `phase_offset + phase_offset_float - 0.5`**

对绝对式编码器（`mode_ & MODE_FLAG_ABS`），`count_in_cpr_` 每周期直接被绝对读数覆盖，
**不受 `phase_offset` 影响**，所以硬件零位和软件偏移是两条独立路径，可以互相换算：

| 状态 | 硬件 ZPOS | 电气 0 处计数 | `phase_offset` | `phase_offset_float` |
|---|---|---|---|---|
| 只做 A | 0 | X | **X** | **0.5** |
| 做 B | X | 0 | **0** | **0.5** |

**绝对不要两个都做**，否则重复补偿 X 个计数。误差换算成电角度是 `X × pole_pairs / 16384` 圈，
按 X=780、pole_pairs=4 算就是 68° 电角度，电机直接失步。

### 2.4 X 的多值性（重要）

电气零点每个电周期出现一次，即每 `16384 / pole_pairs` 个计数重复。直流对齐只会把**离得最近的那个磁极**
拉到定子磁场方向，所以转子起始位置不同，测到的 X 会相差整数倍 `16384 / pole_pairs`。

例：实测两次得到 X = 2987 和 7040，差 4053，而 `16384 / 4 = 4096` —— 当 `pole_pairs = 4` 时两者
指的是同一个电气位置（剩余 43 个计数是直流对齐的重复性误差）。**两个值都是合法的。**

## 3. 固件实现要点

### 3.1 搭周期读的便车，绝不往 SPI 仲裁器插新事务

所有标定/烧写帧都是**临时改写 `encoder_.spi_task_` 本周期要发的那一帧**，仲裁器链表长度恒为 1，
与正常周期读完全一致。

原因（踩过的坑）：从线程往 `Stm32SpiArbiter` 里额外插一笔阻塞事务时，如果某次 `start()` 返回 false，
该任务会**永久卡在链表表头**——因为链表非空时 `transfer_async()` 不再调用 `start()`，只能靠
`on_complete()` 推它，而 `on_complete()` 也不会再被触发。结果周期读连续 51 ms 收不到样本，
累计触发 `ENCODER_ERROR_ABS_SPI_COM_FAIL`，并且调用线程会在等待回调的 `while` 里**永久挂死**
（表现为 CAN 无应答）。

### 3.2 CAN 线程绝不长时间阻塞

`can_server_thread` 的正常收发只在 `HAL_CAN_GetError() == HAL_CAN_ERROR_NONE` 时才执行，
原实现只额外处理了 `HAL_CAN_ERROR_TIMEOUT`：

```cpp
if (status == HAL_CAN_ERROR_NONE) { ...收发... }
else if (status == HAL_CAN_ERROR_TIMEOUT) { ...复位... }
// 其它错误码落不到任何分支 → for(;;) 空转死循环，永远出不来
```

任何其它错误码（ACK 错、位错、error-passive、bus-off…）都会让 CAN **彻底卡死**，而且
`HAL_CAN_ErrorCallback` 是空的，错误码没人清。已改为无条件复位 + 重启 + `osDelay(1)` 让出 CPU。

**因此 OTP 烧写被拆成 `start` / `poll` 两半**，CAN 线程只发起、不等待，结果由
`service_stack()` 每轮循环查询后主动上报。

### 3.3 `is_ready_` / `pre_calibrated` 的死锁

`phase_` 只在 `is_ready_` 为 true 时更新；而 `MODE_SPI_ABS_AMS` 下 `is_ready_` 只在 `abs_spi_cb`
里、且 `config_.pre_calibrated` **已经**为 true 时才置起。

同时 `check_pre_calibrated()`（只由 `set_pre_calibrated()` 调用）会在 `pre_calibrated && !is_ready_`
时把 `pre_calibrated` 改回 false。

所以**通过接口去设 `pre_calibrated = true` 会互相等待、永远置不上**。正确做法是直接给
`config_.pre_calibrated` 赋值，绕过 setter（本工程 0x277 处理里就是这么做的）。

### 3.4 参数

| 项 | 值 |
|---|---|
| 采样率 / 帧间隔 | 8 kHz / 125 µs |
| 标定序列（读+可选写） | 12 帧 ≈ 1.5 ms |
| OTP 序列 | ~40 帧 + 轮询，轮询上限 4000 次（≈1 s） |
| `encoder.config.cpr` | 16384 |
| `phase_offset_float` | 0.5 |
| 对齐电流 / 爬升 | `axis.config.phase_lock_current`（默认 10 A）/ `phase_lock_ramp_time`（默认 0.4 s） |

## 4. CAN 协议

命令帧：**扩展帧 ID `0x277`，DLC = 8**，`byte1 ~ byte7 = 01 02 03 04 05 06 07` 固定校验字，
任一位不符则整帧忽略。

> 本工程的 `0x277` 原本用于"识别/校准命令"（尾缀 `11 22 33 44 55 66 77`）。两者**共用同一 ID，
> 靠固定尾缀区分**，互不重叠：`handle_can_message()` 里先判 `01..07` 尾缀走磁编流程，否则走识别流程。

应答帧：**扩展帧 ID `0x278`，DLC = 8**

```
byte0 = 命令回显（0x00 / 0x11 / 0x33 / 0x44）
byte1 = 数据高 8 位
byte2 = 数据低 8 位
byte3 = 结果码 / 状态位
byte4 = 附加数据（仅 0x00 使用）
byte5-7 = 0
```

`byte1 = byte2 = 0xFF` 表示失败（14 位数据不可能是 0xFFFF，不会误判）。

### 4.1 `byte0 = 0x00` 读磁场强度与诊断信息

```
0x277  00 01 02 03 04 05 06 07
```

流程：读 `MAG(0x3FFD)` → 读 `DIAAGC(0x3FFC)`，**纯读、无副作用**，只占 4 个采样周期（约 0.5 ms），
闭环运行中调用也安全。

应答 `0x278`：

| 字节 | 含义 |
|---|---|
| 0 | `0x00` |
| 1-2 | 磁场强度（MAG，14 bit，byte1 = 高 8 位） |
| 3 | 诊断状态位 |
| 4 | AGC 值 |

byte3 状态位：bit0 = LF（内部偏移补偿环路已完成），bit1 = COF（CORDIC 溢出），
bit2 = MAGH（磁场过强），bit3 = MAGL（磁场过弱）。

DIAAGC 原始位定义（手册 Figure 21）：`bit7:0 = AGC`，`bit8 = LF`，`bit9 = COF`，`bit10 = MAGH`，`bit11 = MAGL`。

读取失败时：`byte1/2 = 0xFFFF`、`byte3 = 0xFF`、`byte4 = 0xFF`。

> 正常安装时 LF 应为 1，MAGH/MAGL/COF 都为 0。用 MAG 和 AGC 判断磁铁与芯片的间隙是否合适。

### 4.2 `byte0 = 0x11` 锁定到电角度 0 并读回 X

```
0x277  11 01 02 03 04 05 06 07
```

流程：

1. 把 axis0 切到 `AXIS_STATE_PHASE_LOCK_ZERO`（自定义状态 14，**开环直流对齐**：定子磁场固定在
   定子空间的电角度 0，相位源被切到 `open_loop_controller_.phase_`，不经过编码器，所以是真对齐，
   与当前 `phase_offset` 对不对无关）；
2. 等状态机进入该状态 → 等电流按 `phase_lock_ramp_time` 爬到设定值并稳定 200 ms → 等转子静止
   （连续 2 ms 内计数变化 ≤ 4）；
3. 读回 `ZPOSM`、`ZPOSL`、`ANGLECOM`，**不做任何写操作**；
4. 反解 `X = (count + ZPOS) mod 16384`；
5. 设 `phase_offset = count`、`phase_offset_float = 0.5`、`pre_calibrated = true`（直接赋值）；
6. 应答 `0x278: 11 <X_H> <X_L> 00 ...`。

**无副作用**是关键：不写 ZPOS，所以反复执行不会把偏移一轮轮叠加；上电后读到的 ZPOS 始终等于
OTP 里的内容，`0x44` 才能判断是否已烧过。

锁定期间 CAN 线程最长阻塞约 1.6 s（500 ms 等状态 + ramp + 200 ms 等稳定 + 500 ms 等静止）。
等待循环里反复喂狗；想缩短可调小 `axis.config.phase_lock_ramp_time`。

### 4.3 `byte0 = 0x22` 退出锁定

```
0x277  22 01 02 03 04 05 06 07
```

axis0 回 `AXIS_STATE_IDLE` 并 disarm。**无应答。**

### 4.4 `byte0 = 0x33` 把 X 软写进 ZPOSM/ZPOSL（易失）

```
0x277  33 01 02 03 04 05 06 07
```

1. 校验轴静止；
2. 用 `0x11` 缓存的 X：写 `ZPOSM = X >> 6`、`ZPOSL = X & 0x3F`，读回 ZPOSM 校验写入生效；
3. 设 `phase_offset = 0`、`phase_offset_float = 0.5`、`pre_calibrated = true`；
4. 应答 `0x278: 33 <C_H> <C_L> 00 ...`，C 为写入后读回的计数，**应在 0 附近**。

必须用 `0x11` 缓存的 X，**不能现场重读**：写 ZPOS 是整体平移，只要 X 是在电气 0 处测到的，
之后转子漂到哪都对；现场重读会把漂移后的错误位置固化成零位。

> ZPOSM/ZPOSL 是**易失寄存器**，掉电丢失。软写后再掉电，计数会变回 X，而 `phase_offset = 0`
> 还留在 flash 里 —— 两者错配 X 个计数，**上电即失步**。走这条路每次上电都要重发 `0x11 + 0x33`，
> 否则请用路线 A（只 `0x11`）或烧 OTP。

### 4.5 `byte0 = 0x44` 把 X 烧进 OTP（**不可逆**）

```
0x277  44 01 02 03 04 05 06 07
```

**前置条件（任一不满足立即拒绝，结果码 6）**：

- 已发过 `0x11` 拿到 X；
- **上电后没往 ZPOS 软写过**（即没发过 `0x33`）；
- 当前处于 `AXIS_STATE_IDLE`。

**应答分两条**：

| 帧 | 时机 | byte1/2 | byte3 |
|---|---|---|---|
| 第 1 条 | 立即 | `FFFF` | `0` = 已开始；`6` = 前置条件不满足；`7` = 上次还在跑 |
| 第 2 条 | 序列跑完后（几十 ms ~ 1 s）由 `service_stack()` 主动上报 | 从 OTP 刷新后读回重建的零位 | 最终结果码 |

**结果码**：

| 码 | 含义 | 处置 |
|---|---|---|
| 0 | 成功（仅出现在第 1 条） | — |
| 1 | SPI 超时 | 可重试，OTP 未动 |
| 2 | 烧前比对不符 | **OTP 未动**，可重试 |
| 3 | PROG 轮询超时 | **PROGOTP 已置位但没等到完成，芯片状态不明，不要再烧** |
| 4 | 烧后比对不符 | 芯片可能已烧坏，不要再烧 |
| 5 | OTP 已烧过 | 预检在**任何写操作之前**中止，什么都没动，安全 |
| 6 | 前置条件不满足 | 按提示补条件 |
| 7 | 上一次还在进行中 | 等第 2 条应答 |

**电气前提（手册 Figure 37，动手前务必确认）**：

| 参数 | 要求 |
|---|---|
| VDD（3.3 V 模式） | **3.3 ~ 3.5 V** |
| VDD（5 V 模式） | 4.5 ~ 5.5 V |
| IProg | 烧写瞬时最大 **100 mA** |
| 温度 | 25 °C ± 20 °C |
| 重烧 | **不允许**（"A reprogramming is not allowed"） |

标准 3.3 V LDO 很可能贴着下限甚至越界。**烧写前先量编码器供电脚的实际电压**。

**固件执行的步骤（手册 step 2~15）**：

1. 预检：读 0x0016/0x0017，非 0 说明已烧过 → 中止（结果码 5）；
2. 写 `ZPOSM = X>>6`、`ZPOSL = X&0x3F`、`SETTINGS1 = 0x0000`、`SETTINGS2 = 0x0000`；
3. 读回 0x0016~0x0019 比对（SETTINGS1 的 bit0 读回恒为 1，比对时屏蔽）→ 不符则中止（结果码 2）；
4. `PROG = 0x0001`（PROGEN=1），隔 2 帧（250 µs，满足手册 ≥100 µs）后 `PROG = 0x0008`（PROGOTP=1）；
5. 轮询读 `PROG` 直到 `0x0001`；
6. 把 0x0016~0x0019 全部写 0（清空易失内容）；
7. `PROG = 0x0040`（PROGVER=1）；`PROG = 0x0004`（OTPREF=1，用 OTP 刷新易失内容）；
8. 读回 0x0016~0x0019 比对 → 这才是"真烧进去了"的凭据（结果码 4 表示失败）；
9. 成功后固件自动设 `phase_offset = 0`、`phase_offset_float = 0.5`、`pre_calibrated = true`。

**手册 step 1 / 16~19（上电与复验）必须由人工完成**：

> **烧完一定要断电重新上电**，再发一次 `0x11` 核对读数。第 2 条应答的 `byte1/2` 应等于烧进去的 X。

## 5. 操作流程

### 5.1 调试 / 验证（不烧 OTP）

```
上电 → 0x11 → 0x22 → 0x33 → 启动闭环，小幅点动确认出力方向
```

### 5.2 写入 flash 的软件偏移（路线 A，掉电安全）

```
1. 0x11  → 记下应答 byte1/2 组成的 X
2. 0x22
3. 把 phase_offset = X、phase_offset_float = 0.5 写进代码 / 用 save_configuration 存 flash
4. 直接进闭环
```

### 5.3 烧 OTP（路线 B，量产）

```
1. 确认供电 3.3~3.5 V、温度 25±20 °C
2. 冷启动（务必是重新上电后的状态）
3. 0x11 → 记下 X；连发 5 次看 X 的重复性
4. 0x22
5. 0x44 → 收第 1 条(byte3=0)，等第 2 条
6. 第 2 条 byte3 = 0 且 byte1/2 == X → 成功
7. 断电重新上电，再发 0x11 复验（手册 step 16~19）
8. 代码里改为 phase_offset = 0、phase_offset_float = 0.5、pre_calibrated = true
```

> **全程不要发 `0x33`**，否则预检失效，必须重新上电再来。

## 6. 注意事项

### 6.1 `direction` 不受本流程覆盖

`phase_ = wrap_pm_pi(ph) * direction`。`run_phase_lock_zero()` 是开环直流对齐，天然测不出方向符号，
既不检查也不设置 `direction`。**方向错了就是正反馈，直接飞车。**

沿用之前标定好的值，或手转轴确认：读数增大的方向对应 `direction = 1`。
也可先跑一次 `AXIS_STATE_ENCODER_DIR_FIND`。

### 6.2 直流对齐的重复性

实测两次 X 相差 43 个计数（`pole_pairs = 4` 时约 3.8° 电角度）。烧 OTP 前建议连发几次 `0x11`
观察抖动；抖动偏大时先把 `phase_lock_current` 调大让磁场更"硬"，对齐更稳定。
电压模式（电机未校准）下把 `phase_lock_voltage` 调到能让转子明显被拉住的电压。

### 6.3 对齐精度与分辨率

整数计数的分辨率是 `pole_pairs × 360 / 16384` 电角度（`pole_pairs = 4` 时约 0.088°），
远高于直流对齐本身的误差，所以 `phase_offset_float` 固定取 0.5 即可，不需要做分数补偿。

## 7. 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `ENCODER_ERROR_ABS_SPI_COM_FAIL` | 早期版本从线程往仲裁器插阻塞事务，任务卡死在链表表头，周期读断供 51 ms | 已改为搭周期读便车；不要恢复旧写法 |
| CAN 无任何应答、且永久不恢复 | `can_server_thread` 遇到 NONE/TIMEOUT 之外的错误码时空转死循环 | 已修复；早期版本需断电重启 |
| `0x11` 应答 `byte1/2 = FFFF` | 轴未静止 / SPI 读取失败 / 状态机超时 / 编码器模式不是 `MODE_SPI_ABS_AMS` | 确认 0x22 后轴确实不动；确认 `board.h` 打开的是 `ENCODER_USE_SPI_ABS_AMS` |
| `0x11` 后电机不动或有异响 | `phase_lock_current` 太小 / 电机未标定走了电压模式 | 加大电流或先做电机标定 |
| `0x33` 后计数不在 0 附近 | ZPOS 未写进去（读回校验失败） | 检查 SPI；结果码会给出失败原因 |
| `0x44` 立即应答 `byte3 = 6` | 没先发 0x11 / 已发过 0x33 / 不在 IDLE | 重新上电后按 5.3 重来 |
| `0x44` 结果码 `5` | 这颗芯片的 OTP 已经烧过 | 预检未动任何东西；直接使用即可 |
| 上电后电机不转 / 失步 | OTP 烧成功但代码里 `phase_offset` 还是 X（应改 0）；或 `direction` 错 | 按 5.3 第 8 步修正 |
